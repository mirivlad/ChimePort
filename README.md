# ChimePort

> **Your alerts. Your server.**
>
> Рабочее название. Статус: **ранний экспериментальный серверный прототип** (без релиза). Android и PWA/Web Push ещё не реализованы.

**ChimePort** — свободная self-hosted система персональных уведомлений. Установите собственный сервер через Docker/Portainer, создайте пользователей, каналы и подписанные источники сообщений, затем читайте уведомления в веб-панели. PWA и универсальный Android-клиент находятся в планах.

Один Android-клиент может быть подключён к **нескольким независимым серверам**, а общая лента объединяет сообщения всех подключений без передачи их в центральное облако проекта.

## Идея за 30 секунд

```text
Home Assistant / Zabbix / скрипты / приложения
                   |
              HTTPS + токен
                   v
          ChimePort (свой домен)
           |       |         |
         SQLite  Web/PWA   Поток событий
                             |
                    Android: 1...N серверов
```

- Администратор создаёт учётные записи; публичной регистрации нет.
- Пользователь создаёт несколько API-токенов с именем, описанием, правами и возможностью отзыва.
- Источники публикуют сообщения в разрешённые каналы; каналы можно подписывать и настраивать.
- Есть общая лента, отдельные каналы, история и синхронизация после офлайна.
- В планах для Android: индивидуальные звуки, графики тишины, фильтры по серверу/каналу.
- Сейчас в вебе: интерфейс и SSE; PWA с Web Push планируется.
- Сервер остаётся полностью самостоятельным; обязательного общего хаба и обязательного Firebase нет.

## Главный принцип доставки

**Успешно принятое сообщение сохраняется на сервере. Немедленное появление уведомления на телефоне не гарантируется.** Клиент восстанавливает пропущенную историю после переподключения; push и постоянные соединения — лишь способы ускорить информирование.

Это не система сертифицированного аварийного оповещения, от которой зависит жизнь или безопасность.

## Быстрый пример работающего API

```bash
curl -X POST 'https://chime.mirv.top/api/v1/messages' \
  -H 'Authorization: Bearer YOUR_SOURCE_TOKEN' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 8d4d52a4-61c2-4bcf-af9a-4a2f30c3fa42' \
  -d '{
    "channel": "home/security",
    "title": "Входная дверь",
    "body": "Дверь открыта",
    "priority": "high"
  }'
```

> **Внимание:** этот маршрут реализован в серверном прототипе; для отправки сначала разверните сервер, создайте канал, источник и токен.

## Статус и лицензия

- Сервер и веб-панель находятся в `main`. GitHub Actions публикует экспериментальный Docker-образ `ghcr.io/mirivlad/chimeport:main` после успешной сборки; это не стабильный релиз. Android-клиента и PWA/Web Push ещё нет.
- Название **ChimePort** предварительное и требует отдельной проверки марки/доменов.
- Open-source лицензия ещё не выбрана; до её добавления права на использование исходного кода другими лицами не предоставлены автоматически.
- Для первых релизов планируется русский и английский интерфейс.

## Будущая структура репозитория

```text
server/          # API, хранение, авторизация, поток событий
web/             # Панель пользователя и администратора, PWA
android/         # Универсальный клиент Kotlin + Compose
deploy/          # Docker, Portainer, примеры конфигурации
docs/            # Требования и архитектурные решения
examples/        # Скрипты и интеграции
```

Структура реализуется постепенно, первый серверный прототип уже находится в `main`.

## Веб-интерфейс

Каналы создаются по названию с автоматическим техническим кодом (slug). Для каждого источника токен создаётся в отдельной форме с выбором разрешённых каналов **галочками**, без ввода числовых ID. В карточке токена можно посмотреть права, срок действия и повторно скопировать секрет. Админская панель адаптирована для мобильного браузера.

## Экспериментальный запуск сервера

Требуется Go 1.23+ и доступ к Go modules или Docker с доступом к registry/module proxy.

```bash
cd server
go mod tidy
go test ./...
CHIMEPORT_DATA_DIR=./data go run ./cmd/chimeport bootstrap --username admin --password-file /secure/path/admin-password.txt
CHIMEPORT_DATA_DIR=./data CHIMEPORT_PUBLIC_URL=http://localhost:8080 go run ./cmd/chimeport serve
```

Локально сервер откроется на `http://localhost:8080`. Команда bootstrap запускается **однократно**, после создания администратора пароль хранится только в виде Argon2id-хэша. Для публичного домена требуется HTTPS reverse proxy. Данные SQLite и ключ `token-key` должны храниться в одном постоянном томе. Для установки через Portainer используйте [пошаговое руководство](docs/11-PORTAINER-QUICKSTART.md) и `deploy/compose.portainer.yaml`; `deploy/compose.yaml` остаётся файлом для сборки из исходников.

### Токены источников

Токен публикации **можно посмотреть повторно** в веб-панели в любой момент, пока он не отозван: кнопки «Показать», «Копировать», «Отозвать». Полный секрет скрыт по умолчанию, хранится в зашифрованном виде и доступен только владельцу источника через пользовательскую сессию. Публиковать токен может только в разрешённые каналы; чтение истории и администрирование по нему запрещены.
