# ChimePort

> **Your alerts. Your server.**
>
> Рабочее название. Статус: **v0.1.0 (первая версия, Android alpha)**: сервер, веб-панель и Android-клиент работают. PWA/Web Push ещё в планах.

**ChimePort** — свободная self-hosted система персональных уведомлений. Установите собственный сервер через Docker/Portainer, создайте пользователей, каналы и подписанные источники сообщений, затем читайте уведомления в веб-панели. Android-клиент уже реализован; PWA с Web Push остаётся следующим крупным этапом.

Один Android-клиент может быть подключён к **нескольким независимым серверам**, а общая лента объединяет сообщения всех подключений без передачи их в центральное облако проекта.

## Идея за 30 секунд

```text
Home Assistant / Zabbix / скрипты / приложения
                   |
              HTTPS + токен
                   v
          ChimePort (свой домен)
           |       |         |
         SQLite  Web/PWA   Поток событий
                             |
                    Android: 1...N серверов
```

- Администратор создаёт учётные записи; публичной регистрации нет.
- Пользователь создаёт несколько API-токенов с именем, описанием, правами и возможностью отзыва.
- Источники публикуют сообщения в разрешённые каналы; каналы можно подписывать и настраивать.
- Есть общая лента, отдельные каналы, история и синхронизация после офлайна.
- Android: звуки по каналам, тихие часы, срочные уведомления, фильтры, поиск и best-effort фоновая доставка.
- В вебе есть панель и SSE; PWA с Web Push пока не реализованы.
- Сервер остаётся полностью самостоятельным; обязательного общего хаба и обязательного Firebase нет.

## Главный принцип доставки

**Успешно принятое сообщение сохраняется на сервере. Немедленное появление уведомления на телефоне не гарантируется.** Клиент восстанавливает пропущенную историю после переподключения; push и постоянные соединения — лишь способы ускорить информирование.

Это не система сертифицированного аварийного оповещения, от которой зависит жизнь или безопасность.

## Быстрый пример работающего API

```bash
curl -X POST 'https://chime.mirv.top/api/v1/messages' \
  -H 'Authorization: Bearer YOUR_SOURCE_TOKEN' \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 8d4d52a4-61c2-4bcf-af9a-4a2f30c3fa42' \
  -d '{
    "channel": "home/security",
    "title": "Входная дверь",
    "body": "Дверь открыта",
    "priority": "high"
  }'
```

> **Внимание:** этот маршрут реализован в серверном прототипе; для отправки сначала разверните сервер, создайте канал, источник и токен.

## Статус и лицензия

- Сервер, веб-панель и Android-клиент находятся в `main`. GitHub Actions публикует экспериментальный Docker-образ `ghcr.io/mirivlad/chimeport:v0.1.0` после успешной сборки; это первая версионированная версия (Android остаётся alpha). Android-клиент работает; PWA/Web Push пока нет.
- Название **ChimePort** предварительное и требует отдельной проверки марки/доменов.
- Лицензия исходного кода: AGPL-3.0-only (см. [LICENSE](LICENSE)).
- Для первых релизов планируется русский и английский интерфейс.

Структура реализуется постепенно, первый серверный прототип уже находится в `main`.

## Веб-интерфейс

Каналы создаются по названию с автоматическим техническим кодом (slug). Для каждого источника токен создаётся в отдельной форме с выбором разрешённых каналов **галочками**, без ввода числовых ID. В карточке токена можно посмотреть права, срок действия и повторно скопировать секрет. Админская панель адаптирована для мобильного браузера.

## Экспериментальный запуск сервера

Требуется Go 1.23+ и доступ к Go modules или Docker с доступом к registry/module proxy.

```bash
cd server
go mod tidy
go test ./...
CHIMEPORT_DATA_DIR=./data go run ./cmd/chimeport bootstrap --username admin --password-file /secure/path/admin-password.txt
CHIMEPORT_DATA_DIR=./data CHIMEPORT_PUBLIC_URL=http://localhost:8080 go run ./cmd/chimeport serve
```

Локально сервер откроется на `http://localhost:8080`. Команда bootstrap запускается **однократно**, после создания администратора пароль хранится только в виде Argon2id-хэша. Для публичного домена требуется HTTPS reverse proxy. Данные SQLite и ключ `token-key` должны храниться в одном постоянном томе. Для установки через Portainer используйте [пошаговое руководство](docs/11-PORTAINER-QUICKSTART.md) и `deploy/compose.portainer.yaml`; `deploy/compose.yaml` остаётся файлом для сборки из исходников.

### Токены источников

Токен публикации **можно посмотреть повторно** в веб-панели в любой момент, пока он не отозван: кнопки «Показать», «Копировать», «Отозвать». Полный секрет скрыт по умолчанию, хранится в зашифрованном виде и доступен только владельцу источника через пользовательскую сессию. Публиковать токен может только в разрешённые каналы; чтение истории и администрирование по нему запрещены.

## Ограничение публикаций и срок хранения

На каждый токен источника действует лимит 120 новых сообщений за календарную минуту UTC (`CHIMEPORT_PUBLISH_RATE_PER_MINUTE`). Превышение возвращает HTTP 429 и `Retry-After`; идемпотентный повтор уже принятого сообщения лимит не расходует. Значение 0 отключает лимит.

Сообщения хранятся 30 дней (`CHIMEPORT_RETENTION_DAYS`); 0 отключает очистку. Очистка выполняется при запуске сервера и затем раз в сутки. Удаление необратимо без бэкапа, а SQLite v3 не поддерживается старым сервером без восстановления прежней базы. Подробнее: [развёртывание](docs/06-DEPLOYMENT.md).

## Резервное копирование и восстановление

Сервер поддерживает согласованные снимки SQLite WAL, резервирование ключа токенов, контрольные суммы и SQLite integrity/foreign key checks. Аварийное восстановление возможно **в новый пустой каталог с сохранением старого Docker volume**, а для отката кода публикуются неизменяемые GHCR-теги `sha-<полный SHA коммита>`. Пошаговая инструкция и скрипт для Docker-хоста: [docs/13-BACKUP-RESTORE.md](docs/13-BACKUP-RESTORE.md). Веб-мастер восстановления и автоматическая ротация копий пока не реализованы.

## Учётные записи и доступ

Веб-панель позволяет пользователю сменить собственный пароль. В разделе **Пользователи** администратор может сбросить пароль другого аккаунта и заблокировать/разблокировать его. При смене/сбросе пароля все пользовательские сеансы отзываются, Android попросит повторный вход. Отдельные токены источников при смене пароля сохраняются; блокировка аккаунта запрещает публикации через принадлежащие ему токены. Подробнее: [API и модель доступа](docs/03-API.md).

- Для локального администратора добавлена команда создания интеграционного источника с приватным токен-файлом:

```bash
chimeport integration provision --username admin --source home-assistant \
  --label ha --channels home/door,home/weather --token-out /data/ha-token.tmp
```

Токен сохраняется только в новом файле с правами 0600; команда не выводит секрет в консоль. После переноса в защищённые secrets другого приложения временный файл удалить. Для остальных проектов создавать собственные источники и токены.
