# ChimePort + Home Assistant: рабочий пример интеграции

Эта конфигурация проверена на Home Assistant 2026.1.3 и ChimePort v0.1.0. Отправка делается через штатный `rest_command`, без HACS, кастомных компонентов и дополнительных плагинов.

**Безопасность:** в примерах используется только зарезервированный домен `notify.example.org` и заведомо недействительный токен `cp_t_EXAMPLE_NOT_A_REAL_TOKEN`. Никаких реальных адресов, сущностей из домашнего HA или ключей в репозитории нет. Не публикуйте свой `secrets.yaml`, бэкапы HA и журнал с заголовками Authorization.

## 1. Создайте источник и каналы в ChimePort

Зайдите в свой ChimePort под пользователем, которому должны приходить уведомления (обычно тем же, что использует Android-клиент).

1. Создайте источник с именем `home-assistant`.
2. Создайте каналы `home/door`, `home/weather`, `home/climate`, `home/sensors`, `home/system` (допускается выбрать только нужные).
3. Выдайте **отдельный токен источника** с правом публикации **только** в эти каналы. Админ-пароль или пользовательскую сессию для отправки не используйте.
4. Скопируйте токен в защищённое место. Для владельца Docker volume также доступна локальная команда `chimeport integration provision` (см. `docs/06-DEPLOYMENT.md`): она создаёт источник, каналы и приватный файл токена с режимом `0600`.

Для каждого другого приложения создавайте собственный источник и отдельный токен; доступ ко всем каналам по умолчанию не выдавайте.

## 2. Настройте секрет

Откройте `/config/secrets.yaml` в Home Assistant. Добавьте запись по образцу [secrets.yaml.example](secrets.yaml.example), но **подставьте свой токен, а не примерный**:

```yaml
chimeport_bearer: "Bearer cp_t_EXAMPLE_NOT_A_REAL_TOKEN"
```

Права на файл — только владельцу (`chmod 600` для обычной файловой конфигурации Linux; владелец должен совпадать с учётной записью, читающей конфигурацию HA). Не создавайте второй ключ с тем же именем.

## 3. Добавьте REST-команду

В `/config/configuration.yaml` добавьте содержимое [configuration.fragment.yaml](configuration.fragment.yaml), **не заменяя** остальную конфигурацию. Измените `https://notify.example.org` на свой HTTPS-адрес ChimePort.

Если у вас уже есть секция `rest_command:`, добавьте в неё **только** вложенный блок `chimeport_publish:`, не создавая второй `rest_command:`.

В HTTP-заголовке будет `Authorization: Bearer …`. Отправляемый JSON содержит `channel`, `title`, `body`, `priority`; параметр автоматизации `message` превращается в поле `body`. Фильтр Jinja `to_json` правильно экранирует кавычки и переводы строк.

## 4. Проверьте тестовой отправкой

Проверьте конфигурацию штатной функцией HA (`ha core check` для HA OS либо `python -m homeassistant --script check_config -c /config` внутри Docker-контейнера). Перезапустите HA, чтобы загрузилась новая `rest_command`.

В **Инструменты разработчика → Действия → YAML** выполните:

```yaml
action: rest_command.chimeport_publish
data:
  channel: home/door
  title: "Проверка ChimePort"
  message: "Тестовое уведомление из Home Assistant"
  priority: normal
```

Ожидаемый HTTP-ответ: `status: 201` с `stored: true` (или `200` для идемпотентного повтора, если используется соответствующий ключ). Затем проверьте веб-панель ChimePort и реальную доставку на Android. Ответ HTTP **не гарантирует** показа на телефоне.

## 5. Подключите свои автоматизации

Файл [automations.example.yaml](automations.example.yaml) содержит образцы для двери, долгого открытия, температуры, батареек, климата, погоды и запуска/остановки HA. Его **не нужно целиком заменять** вместо собственного `automations.yaml`.

В существующей автоматизации достаточно **добавить ещё одно действие после Telegram**:

```yaml
  - action: rest_command.chimeport_publish
    data:
      channel: home/door
      title: "Входная дверь"
      message: "Открыта"
      priority: high
```

**Telegram оставляем включённым**. В нашем варианте это постоянный параллельный канал, а не временный fallback. Не удаляйте и не редактируйте существующее Telegram-действие.

Для пороговых событий используйте `numeric_state` (например, `above: 30` / `below: 15`), а для открытой 5 минут двери — `state: on` с `for: "00:05:00"`. Проверяйте, что триггеры не равны `[]`, иначе автоматизация не запустится сама.

Для длительного открытия двери уместен `urgent` (может обходить тихие часы, если Android настроен соответствующим образом). Для обычной погоды и старта HA — `normal`. Оповещение об остановке HA — **best effort**: приложение может прекратить работу до завершения HTTP-запроса. Для контроля доступности HA снаружи используйте отдельный мониторинг.

## 6. Проверка проблем

- `401/403`: неверный токен, токен отозван, или у него нет доступа к указанному каналу.
- `404`: проверьте `/api/v1/messages` и фактический домен.
- `429`: лимит частоты публикации; учитывайте заголовок `Retry-After` (HA `rest_command` сам не строит долговечную очередь).
- `201`, но нет уведомления на Android: проверьте вход в тот же ChimePort-аккаунт, разрешение уведомлений, подписки/каналы, настройки батареи Android.
- Отправка не идёт: посмотрите трассировку конкретной автоматизации HA и статус `rest_command`; проверьте DNS/TLS из контейнера HA.
- Если UI не показывает команду, проверьте `check_config` и перезапустите HA.

Все имена `entity_id` в примерах вымышлены: замените их на реальные из **Инструменты разработчика → Состояния**.
