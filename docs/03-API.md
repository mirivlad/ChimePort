# ChimePort API v1

**Реализованный контракт сервера v0.1.2** (05.11.2026). Базовый URL: `https://YOUR-DOMAIN/api/v1`. Все пути в таблицах указаны относительно него; для сообщений используется JSON UTF-8 и время RFC 3339. См. [быстрый запуск](11-PORTAINER-QUICKSTART.md).

## Два типа полномочий

- **Пользовательская сессия** (`cp_s_…`): выдаётся после `POST /auth/login`, действует 7 дней. В режиме `"mode":"web"` сервер устанавливает HttpOnly cookie; в режиме `"mode":"api"` возвращает Bearer `access_token` для Android и API-клиентов. Серверная авторизация одинаково проверяет роли. **Маршрут refresh token не реализован**: по окончании срока требуется повторный вход.
- **Токен источника** (`cp_t_…`): только `POST /messages`, только в явно разрешённые каналы. Он не открывает историю, не изменяет статус прочтения, не администрирует пользователей.

Для изменяющих запросов с **cookie** требуется точный заголовок `Origin`, равный `CHIMEPORT_PUBLIC_URL`. Для Bearer-клиентов (включая Android) применяется HTTPS и проверка токена. Полный секрет источника можно повторно показать владельцу через отдельный endpoint; храните его вне журналов и URL.

## Реализованные маршруты

### Публичные и вход

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health/live` | Liveness (это **корневой путь**, не `/api/v1/…`) |
| GET | `/health/ready` | Readiness с проверкой SQLite (корневой путь) |
| GET | `/instance` | `instance_id`, `api_version`, имя сервера |
| POST | `/auth/login` | `{"username":"…","password":"…","mode":"web"}`; `mode` может быть `api` |
| POST | `/auth/logout` | Завершить текущую сессию |
| GET | `/me` | Сведения о вошедшем пользователе |
| POST | `/me/change-password` | Изменить собственный пароль; все сессии отзываются |

### Каналы, источники и токены (пользователь)

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET / POST | `/channels` | Список / создание собственных каналов |
| PATCH | `/channels/{id}` | Изменить название и описание; slug неизменяем |
| GET / POST | `/sources` | Список / создание собственных источников |
| PATCH | `/sources/{id}` | Изменить название и описание |
| GET / POST | `/sources/{id}/tokens` | Список метаданных / выпуск нового токена |
| GET | `/sources/{id}/tokens/{token_id}/secret` | Повторно получить действующий токен |
| PATCH | `/sources/{id}/tokens/{token_id}` | Заменить права на каналы (без перевыпуска секрета) |
| DELETE | `/sources/{id}/tokens/{token_id}` | Отозвать токен |

При создании токена задаются название/описание, набор разрешённых `channel_ids` и необязательный срок. У токенов есть срок жизни, статус и отзыв. Для PATCH прав используется тело `{"channel_ids":[1,2]}` — от 1 до 100 **собственных** уникальных каналов. Для чужих и отозванных токенов возвращается 404.

### Сообщения и события

| Метод | Путь | Доступ и назначение |
| --- | --- | --- |
| POST | `/messages` | **Токен источника:** сохранить сообщение |
| GET | `/messages?after=…&limit=…` | **Пользователь:** страницы своей истории, limit 1–200 (по умолчанию 100) |
| POST | `/messages/{id}/read` | **Пользователь:** отметить прочитанным |
| DELETE | `/messages/{id}/read` | **Пользователь:** снова отметить непрочитанным |
| GET | `/events` | **Пользователь:** SSE, сигнал о новых событиях для последующей REST-синхронизации |

`GET /messages/{id}` **пока отсутствует**. Информация о сообщениях выдаётся историей, а не отдельным detail endpoint. SSE не подменяет хранилище и может пропускать события при разрыве соединения; после переподключения клиент обязан обновить историю.

### Администратор

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET / POST | `/admin/users` | Список / создание пользователей (роли `user`, `admin`) |
| PATCH | `/admin/users/{id}` | `{"disabled":true}` или `false` |
| POST | `/admin/users/{id}/reset-password` | `{"new_password":"…"}` для другого пользователя |

Заблокированный пользователь не может войти; его пользовательские сессии отзываются, токены публикации перестают работать до разблокировки. Смена/сброс пароля отзывают все **пользовательские сессии**, но не source tokens. Запрещено блокировать себя и последнего активного администратора. Пароли 12–128 байт.

## Отправка уведомления

```bash
export CHIMEPORT_URL=https://notify.example.org
read -r -s -p 'Source token: ' CHIMEPORT_TOKEN; printf '\n'
curl --fail-with-body -sS \
  -X POST "$CHIMEPORT_URL/api/v1/messages" \
  -H "Authorization: Bearer $CHIMEPORT_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: backup-2026-11-05T04:00:00Z' \
  -d '{
    "channel": "servers",
    "title": "Бэкап завершён",
    "body": "Ежедневный архив проверен",
    "priority": "normal",
    "tags": ["backup"],
    "url": "https://monitor.example.org/status"
  }'
unset CHIMEPORT_TOKEN
```

`channel` можно передать **в query-параметре** (удобно для интеграций):

```text
POST /api/v1/messages?channel=servers
Authorization: Bearer <source-token>
```

Тогда поле `channel` в JSON необязательно; если передано и там, и там, значения должны совпадать (`400 channel_mismatch`). Секрет **никогда** не передавайте в URL.

**Поля:** `channel` — slug до 80 символов (`[a-z0-9_/-]`, начинается с `[a-z0-9]`); `title` — обязательный непустой текст до 200 Unicode-символов; `body` — до 16 KiB UTF-8; `priority` — `low`, `normal` (по умолчанию), `high`, `urgent`; `tags` — до 10 непустых строк по 40 байт; `url` — только абсолютный HTTPS URL без userinfo. `urgent` не может игнорировать ограничения ОС или системный DND.

**Успешный ответ при создании**: HTTP `201`, тело вида `{"id":"123","channel":"servers","created_at":"2026-11-05T09:00:00Z","stored":true}`. `Location` указывает путь сообщения. Если отправить тот же `Idempotency-Key` с идентичным телом и тем же токеном — `200`, `duplicate:true` и исходный `id`; с другим телом — `409 idempotency_conflict`. Ключ необязателен, но **настоятельно рекомендуется** при сетевых повторах.

**Ограничение частоты:** по умолчанию 120 **новых** сообщений на токен за календарную минуту UTC; повтор с корректным ключом квоту не расходует. При превышении `429 rate_limited` и заголовок `Retry-After` в секундах. Настройка `CHIMEPORT_PUBLISH_RATE_PER_MINUTE` (0 отключает).

Ошибки имеют формат `{"error":{"code":"...","message":"..."}}`. Частые ответы: `400` — неверное тело, `401` — невалидный/просроченный токен, `403 forbidden_channel` — нет права на канал, `409` — конфликт идемпотентности, `429` — rate limit, `500` — ошибка сервера.

## История, прочтение и хранение

`GET /messages` возвращает `items`, `next_cursor`, `has_more` и `retention_gap`. Курсор непрозрачный и не предназначен для самостоятельной генерации; после отсутствия сети запрашивайте следующую страницу и дедуплицируйте сообщения по `(instance_id,message_id)`. `read_at` — статус прочтения конкретным пользователем, не подтверждение показа системного уведомления Android.

Сервер по умолчанию хранит историю **30 дней**, `CHIMEPORT_RETENTION_DAYS=0` отключает удаление. История и связанные записи очищаются при старте и ежедневно; `retention_gap=true` говорит о разрыве при чтении с прежним курсором.

## Что пока не реализовано

Не зарегистрированы: `POST /auth/refresh`, `GET /messages/{id}`, маршруты `/devices` и `/devices/{id}/webpush`, `/settings/notifications`, REST-API для PWA и Web Push. Они встречались в старом дизайн-документе как планы, **но не являются доступным API v1**. Для будущих контрактов см. [roadmap](07-ROADMAP.md).

Для работы в веб-панели есть готовая страница **`/examples`**, где адреса формируются для ваших каналов и сервера без подстановки секретов.
