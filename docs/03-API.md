# 03. API v1 — предварительный контракт

**Все пути/форматы ниже проектируемые, не реализованные.** Базовый URL: `https://your-domain.example/api/v1`. JSON UTF-8. Время в RFC 3339/UTC. Версия API меняется только при нарушении обратной совместимости.

## 1. Типы аутентификации

- **Source token** — `Authorization: Bearer <token>`, только `messages:write` в перечисленные каналы.
- **Пользовательская сессия** — login/password -> короткоживущий access token + обновляемый refresh token в Android; для Web — безопасные HttpOnly-cookie и CSRF-защита. Схема может уточняться, но права типов не должны смешиваться.
- **Администратор** — пользовательская сессия с отдельной ролью и проверкой разрешений на каждом admin endpoint.

API-токены доступны владельцу повторно по явному запросу «Показать» или «Копировать». В списке по умолчанию виден только префикс, полный секрет возвращается отдельным endpoint после аутентификации пользователя. Отозванные токены повторно не показываются. Токены нельзя использовать для входа, чтения сообщений или администрирования.

## 2. Публикация

### `POST /messages` — создать сообщение

Заголовки:

```http
Authorization: Bearer <source-token>
Content-Type: application/json
Idempotency-Key: <random-unique-value>   # рекомендован
```

Тело:

```json
{
  "channel": "home/security",
  "title": "Входная дверь",
  "body": "Дверь открыта",
  "priority": "high",
  "tags": ["home", "door"],
  "url": "https://home.example.org/lovelace/security",
  "expires_at": null
}
```

`channel`: slug только из каналов, куда токен имеет право отправлять. `priority`: `low | normal | high | urgent` (уровень `urgent` **не** даёт автоматического права обходить пользовательские ограничения). `title` и `body` — обычный текст, не произвольный HTML. URL разрешены только `https://` / оговорённые безопасные схемы, без выполнения кода.

Первоначальные лимиты (настраиваемые): заголовок 200 символов, тело 16 KiB UTF-8, теги 10 штук, максимум 10 запросов в секунду на токен с коротким burst. Реальные значения уточняются тестами.

Успех:

```http
HTTP/1.1 201 Created
Location: /api/v1/messages/01J...
```

```json
{
  "id": "01JEXAMPLEID",
  "channel": "home/security",
  "created_at": "2026-11-03T00:00:00Z",
  "stored": true
}
```

Повтор с тем же ключом и идентичным телом возвращает существующий ID (`200 OK` или исходный `201`, решение фиксируется перед реализацией). Повтор того же ключа с другим телом: `409 Conflict`.

Общий формат ошибки:

```json
{
  "error": {
    "code": "forbidden_channel",
    "message": "Token cannot publish to this channel",
    "request_id": "req_..."
  }
}
```

Коды: `400` неверное тело, `401` нет/невалидный токен, `403` нет прав, `404` нет доступной сущности, `409` конфликт ключа, `413` слишком большое сообщение, `429` лимит, `500` серверная ошибка. Ответы `429` включают `Retry-After`.

## 3. Планируемые endpoints

| Метод и путь | Кто | Назначение |
| --- | --- | --- |
| `POST /auth/login` | любой | Вход человека; защита от перебора |
| `POST /auth/refresh` | клиент | Продление сессии |
| `POST /auth/logout` | пользователь | Завершить/отозвать текущую сессию |
| `GET /me` | пользователь | Своя учётная запись и роль |
| `GET /instance` | публично, минимум данных | Версия совместимости API, постоянный ID сервера |
| `GET /channels` | пользователь | Доступные каналы |
| `POST /channels` | пользователь | Создать личный канал |
| `PATCH /channels/{id}` | владелец | Изменить канал |
| `DELETE /channels/{id}` | владелец | Удалить/архивировать (политика retention) |
| `GET /sources` | пользователь | Источники владельца |
| `POST /sources` | пользователь | Создать именованный источник |
| `POST /sources/{id}/tokens` | владелец | Создать ограниченный токен |
| `GET /sources/{id}/tokens` | владелец | Метаданные, префикс и `allowed_channels` (без секрета) |
| `PATCH /sources/{id}/tokens/{token_id}` | владелец | Атомарно заменить разрешённые каналы без смены токена; тело `{"channel_ids":[1,2]}`; от 1 до 100 уникальных собственных каналов. Отозванный/чужой токен: 404 |
| `GET /sources/{id}/tokens/{token_id}/secret` | владелец | Повторно получить полный токен по явному действию, `Cache-Control: no-store` |
| `DELETE /sources/{id}/tokens/{token_id}` | владелец | Отозвать токен |
| `POST /messages` | source token | Опубликовать сообщение |
| `GET /messages?after=...&limit=...` | пользователь | Стабильная выборка доступной истории |
| `GET /messages/{id}` | пользователь | Одно доступное сообщение |
| `POST /messages/{id}/read` | пользователь | Отметить прочитанным |
| `GET /events` | пользователь | WebSocket/SSE, события-индикаторы (не источник истины) |
| `POST /devices` | пользователь | Зарегистрировать устройство |
| `DELETE /devices/{id}` | пользователь | Отвязать устройство, отозвать credentials |
| `POST /devices/{id}/receipts` | пользователь + устройство | Подтвердить получение до watermark / набора ID |
| `POST /devices/{id}/webpush` | пользователь + устройство | Зарегистрировать Web Push subscription |
| `DELETE /devices/{id}/webpush` | пользователь + устройство | Удалить подписку Web Push |
| `GET /settings/notifications` | пользователь | Настройки уведомлений по умолчанию |
| `PUT /settings/notifications` | пользователь | Обновление настроек (дополнительно клиентские overrides) |
| `GET /admin/users` | админ | Список пользователей |
| `POST /admin/users` | админ | Создать аккаунт |
| `PATCH /admin/users/{id}` | админ | Заблокировать/изменить права |
| `POST /admin/users/{id}/reset-password` | админ | Процедура безопасного сброса |
| `GET /health/live` | мониторинг | Liveness (без секретов) |
| `GET /health/ready` | ограниченный доступ | Readiness |

Конкретные тела для admin, settings и devices следует формализовать в OpenAPI перед началом реализации.

## 4. История и курсор

`GET /messages?after=<opaque-cursor>&limit=100` возвращает:

```json
{
  "items": [
    {
      "id": "01JEXAMPLEID",
      "channel_id": "ch_123",
      "channel": "home/security",
      "source": "home-assistant",
      "title": "Входная дверь",
      "body": "Дверь открыта",
      "priority": "high",
      "created_at": "2026-11-03T00:00:00Z",
      "read_at": null
    }
  ],
  "next_cursor": "opaque-value",
  "has_more": false,
  "retention_gap": false
}
```

- Курсор серверный, непрозрачный, устойчив к одновременным вставкам.
- История включает только разрешённые сообщения; клиент не должен угадывать ID соседних пользователей.
- Курсор привязан к идентичности инсталляции и пользователя.
- Если история удалена retention, клиент видит `retention_gap=true` и границу доступности.
- `read_at` — состояние пользователя, `device receipt` — факт приёма клиентом; это разные вещи.

## 5. События в реальном времени

Событие `messages_available` содержит watermark/минимальные идентификаторы, не полное доверенное состояние. Клиент обязательно вызывает REST sync для достоверного списка. Отдельные события `session_revoked`, `channels_changed`, `settings_changed` допустимы. Транспорт не обещает exactly-once; клиент дедуплицирует по `(instance_id, message_id)`.

## 6. План развития API

V1 не требует webhook-ответов, экспорта истории, медиа-вложений и входящих федеративных подписок. Все такие изменения должны быть обратносуместимыми и пройти threat-model review.
