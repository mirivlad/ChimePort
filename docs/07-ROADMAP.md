## M2.1 — Android: исходное ТЗ пилота (реализован в alpha)

**Это не техническая демка.** Урезаем глубину серверной инфраструктуры, а не качество интерфейса. Приложение должно быть приятным настолько, чтобы его хотелось оставить на телефоне. Подробности: [Android pilot UX](12-ANDROID-PILOT.md).

- [ ] Kotlin + Jetpack Compose / Material 3, собственная стилистика ChimePort, красивое оформление, светлая и тёмная темы, адаптивность, русский интерфейс.
- [ ] Первый запуск: адрес произвольного HTTPS-сервера, проверка его доступности и идентичности, вход, безопасная сессия, полезные сообщения об ошибках.
- [ ] Удобная общая лента: красивые читаемые карточки, приоритет, канал, дата, источник, непрочитанное, детализация, фильтры и содержательные пустые состояния.
- [ ] Экран каналов с быстрым просмотром сообщений и счётчиками.
- [ ] Отметка прочитанного, ручное обновление и синхронизация при возвращении в приложение.
- [ ] Локальный кэш истории, отображение без связи, восстановление и дедупликация после переподключения.
- [ ] Полноценное подключение нескольких независимых серверов с отдельными учётными данными, именами и единой лентой.
- [ ] Внятная навигация, плавные и ненавязчивые переходы, аккуратная типографика и доступность.
- [ ] Устанавливаемый APK пилотной версии, воспроизводимая сборка и инструкция для тестирования.
- [ ] Проверки API и поведения приложения, отсутствие фиктивных элементов управления и «Coming soon» вместо основных сценариев.

**Критерий:** с установленного APK можно подключиться к chime.mirv.top, авторизоваться, увидеть отправленное с компьютера сообщение, удобно работать с каналами и прочтением, получить историю после офлайна и подключить второй сервер. Приложение должно хорошо выглядеть на реальном телефоне.

**Пока не требуем:** мгновенный фоновый push при закрытом приложении, постоянный foreground service, расширенную серверную админку, релизную подпись APK. Но интерфейс не должен обещать отсутствующих функций.

### Контрольная точка после M2.1

Испытать ChimePort в повседневной жизни. Собрать замечания к удобству, исправить их и **осознанно решить, продолжать ли проект**. Не переходить автоматически к усложнению инфраструктуры, если сам клиент не нравится.

## Минимальная матрица тестирования

| Сценарий | Проверка |
| --- | --- |
| Повтор сообщения с тем же idempotency key | Ровно одна запись |
| Одновременное создание сообщений | Стабильный порядок/курсор, нет потерь |
| Рестарт после commit перед ответом | Повтор не порождает дубль |
| Телефон offline час | После sync вся сохранённая история |
| Два сервера с одинаковыми message IDs | Нет смешивания данных |
| Удаление/отзыв токена | Публикация отвергается немедленно |
| Пользователь A запрашивает канал B | Нет доступа, нет утечки метаданных |
| Тишина 23:00–08:00 и переход дня | Не звучит в установленный период |
| Без разрешения на push | Лента работает, статус объясняет причину |
| Удалённый канал/истёкший retention | У клиента понятное состояние и sync gap |

> Сервер, веб-панель и Android alpha существуют; в M1.1 реализованы ограничения публикаций и retention. Дальше: OpenAPI, PWA/Web Push, подготовка публичного релиза и интеграции после него.
