# 07. План реализации

**Приоритет:** сначала полный маршрут `API -> durable storage -> web -> Android -> sync`, затем украшения интерфейса и дополнительные транспорты.

## M0 — основание проекта

- [ ] Утвердить название и проверить доступность GitHub/доменов/марок.
- [ ] Выбрать лицензию и создать `LICENSE`.
- [ ] Зафиксировать технологический стек и основные ADR.
- [ ] Создать структуру модулей, CI (lint/test/build), стандарт форматирования и versioning.
- [ ] Формализовать OpenAPI и миграционную стратегию SQLite.

**Готово, когда:** свежий clone собирается и выполняет тесты одной командой; нет фиктивного API без контракта.

## M1 — сервер и веб-панель

- [ ] Безопасный bootstrap администратора, вход и выход.
- [ ] Админское создание пользователей без публичной регистрации.
- [ ] Создание личных каналов, источников, нескольких подписанных и отзываемых токенов.
- [ ] Приём сообщений по REST с commit-before-ack, лимитами и идемпотентностью.
- [ ] Общая лента и страницы каналов, read/unread, базовый поиск/фильтр.
- [ ] Долговременное хранение, retention, backup/restore, стабильный instance ID.
- [ ] Docker Compose + Portainer инструкции и healthcheck.

**Готово, когда:** Home Assistant/`curl` отправляет событие, админ и пользователь видят только доступное; после рестарта всё сохраняется.

## M2 — Android: полноценный клиент

- [ ] Подключение произвольного HTTPS сервера: проверка URL/instance ID, логин, logout.
- [ ] Подключение двух и более серверов в одном приложении.
- [ ] Локальное хранилище с раздельными namespace и единая лента.
- [ ] Прямой онлайн-транспорт, автоматическое переподключение, обязательная sync с курсором.
- [ ] Notification Channels, системный звук, настройка тишины global/server/channel.
- [ ] Экран диагностики, разрешение уведомлений, подсказки по батарее.
- [ ] Подписанный APK через GitHub Releases, воспроизводимый процесс сборки.

**Готово, когда:** 2 независимые инсталляции соединены с одним телефоном; без интернета приходят события на сервер, а после возврата телефон синхронизирует их без дублей и массового звона.

## M3 — PWA и Web Push

- [ ] Manifest, Service Worker, установка как PWA в поддерживаемых браузерах.
- [ ] Web Push subscription/отзыв, отправка событий подписчикам.
- [ ] UX разрешений, диагностическая панель и graceful fallback.
- [ ] Тесты Chrome и Firefox на Android/desktop после закрытия вкладки, перезагрузки и нескольких дней простоя.

**Готово, когда:** PWA сохраняет историю и показывает уведомления при рабочем браузерном push; отсутствие разрешения не ломает веб-приложение.

## M4 — качество и публичный релиз

- [ ] Локализация ru/en, документация установки и миграций.
- [ ] Тестирование безопасности и многопользовательской изоляции.
- [ ] Тестовые матрицы Android OEM, расхода батареи и фоновых ограничений (без безусловных обещаний).
- [ ] CI сборка Docker amd64/arm64 + Android APK, подпись, checksums и релиз-ноты.
- [ ] Нагрузочные и долговременные тесты без истощения диска.

## После MVP

- [ ] Совместно используемые каналы с ACL.
- [ ] UnifiedPush или иной открытый системный транспорт, исследование и прототип.
- [ ] Опциональная FCM-интеграция без обязательного центра проекта.
- [ ] Шаблоны сообщений и простая маршрутизация.
- [ ] iOS-клиент при наличии практической возможности.
- [ ] Дополнительные возможности импорта/экспорта, сброс пароля, возможные приглашения.

## Минимальная матрица тестирования

| Сценарий | Проверка |
| --- | --- |
| Повтор сообщения с тем же idempotency key | Ровно одна запись |
| Одновременное создание сообщений | Стабильный порядок/курсор, нет потерь |
| Рестарт после commit перед ответом | Повтор не порождает дубль |
| Телефон offline час | После sync вся сохранённая история |
| Два сервера с одинаковыми message IDs | Нет смешивания данных |
| Удаление/отзыв токена | Публикация отвергается немедленно |
| Пользователь A запрашивает канал B | Нет доступа, нет утечки метаданных |
| Тишина 23:00–08:00 и переход дня | Не звучит в установленный период |
| Без разрешения на push | Лента работает, статус объясняет причину |
| Удалённый канал/истёкший retention | У клиента понятное состояние и sync gap |
