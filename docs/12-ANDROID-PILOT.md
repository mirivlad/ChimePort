# 12. Android — первая испытательная версия с полноценным UX

**Статус:** утверждённая цель, пока не реализовано. Решение 2026-11-03.

## Цель

Сначала выпустить **красивое, удобное и настоящее Android-приложение**, чтобы оценить ChimePort в обычном использовании. Не переносить всю работу по серверному администрированию в начало, но и не выдавать прототип с сырыми формами за испытательную версию.

**Принцип:** лучше меньше завершённых пользовательских сценариев, чем десятки полурабочих экранов.

## Визуальный стиль

- Нативное приложение на Kotlin + Jetpack Compose и Material 3 с собственным характером ChimePort, не WebView и не копия Telegram.
- Светлая и тёмная темы; цельная система отступов, типографики и цвета; собственная иконка, понятные пиктограммы и ненавязчивые акценты.
- Разборчивая лента с очевидной иерархией: сначала заголовок и содержимое сообщения, затем канал, источник и время.
- Уровни приоритета выражаются деликатно, но заметно; непрочитанное визуально отличается от прочитанного.
- Плавные переходы без тяжёлых анимаций, нормальная работа с большими шрифтами, TalkBack и небольшими экранами.
- Никаких кнопок-пустышек, ручного ввода внутренних идентификаторов и сообщений об ошибках в духе HTTP 500 без объяснения.

## Основные экраны первой версии

### 1. Приветствие и сервер

Первый экран прямо говорит: ChimePort не требует общего облачного аккаунта, сервер выбирает пользователь. Ввод адреса, проверка HTTPS и получения instance ID; понятные ошибки DNS, TLS, таймаута и несовместимой версии. Затем имя пользователя и пароль, необязательная удобная метка сервера («Дом», «Работа»). Показывать реальный домен до ввода пароля.

### 2. Входящие

Домашний экран: общая лента, чёткие карточки, группировка по дате, фильтр каналов, серверов и непрочитанных, детализация длинных сообщений. Pull-to-refresh и синхронизация при возврате в приложение. Пустая лента показывает понятное объяснение и ссылку на страницу примеров отправки своего сервера.

### 3. Каналы

Список названий каналов и количества непрочитанных, открытие отдельной ленты. Никаких raw-ID; технический slug показывать только как дополнительную информацию.

### 4. Серверы

Добавление второго и следующих серверов, изменение локальной метки, отображение точного HTTPS-хоста, статуса соединения и времени последней синхронизации, отключение и удаление с подтверждением. Одинаковые ID сообщений разных серверов не должны смешиваться.

### 5. Настройки и состояние

Выбор системной/светлой/тёмной темы, аккаунты, описание поведения синхронизации, диагностика соединения. Будущие звуки и фоновая доставка не выдаются за готовые функции.

## Данные и синхронизация

- Только настоящие серверные API. Для чтения используется пользовательская сессия; source tokens нужны отправляющим скриптам и не должны использоваться в Android для входа.
- Раздельные учётные данные и локальные namespace по инсталляциям. Идентичность сервера включает origin и instance ID, сообщения различаются парой server ID + message ID.
- Локальный кэш истории, например Room; при отсутствии сети старая история остаётся доступной.
- После восстановления связи синхронизировать страницы по непрозрачному курсору и подавлять дубликаты. Не стирать историю при временных ошибках.
- Отметка прочитанного синхронизируется с сервером; приложение честно показывает состояние, если операция не прошла.
- Работа в фоне и системное звуковое оповещение — следующий этап M2.2, а не фиктивная возможность пилота.

## Практическая приёмка

1. APK устанавливается на реальный телефон без Android Studio и Google Play.
2. Добавление своего адреса chime.mirv.top, вход и переход в ленту понятны без документации.
3. Реальное сообщение из curl или Home Assistant появляется после обновления; все поля отображаются правильно.
4. Каналы читаются и фильтруются, отметка прочитанного сохраняется после перезапуска.
5. При отсутствии интернета история остаётся доступной; восстановление сети не создаёт дублей.
6. Подключение второго независимого сервера не смешивает данные и аккаунты.
7. Интерфейс удобно управляется одной рукой и нормально выглядит в светлой и тёмной темах, с крупным шрифтом и пустыми состояниями.
8. Важно: пользователь должен оценить удобство **до** перехода к следующему этапу. Замечания к UI не откладывать как необязательную полировку.

## Не делаем пока

Web Push, сложную систему разрешений, редактирование серверных API-токенов с Android, обязательный Firebase, масштабную реорганизацию серверной админки. Это не препятствует выпуску хорошего первого клиента.

## UX update for alpha 6

- Inbox contains horizontally scrollable tabs: **Unread**, **All**, and channels. For matching channel names on different servers, also show their server labels.
- Bottom navigation: **Inbox**, **Search**, **Servers**, **Settings**. Search offers filters by server, channel, status and priority.
- Swipe an unread message left to mark it read. Swipe a read message right to move it back to unread. Never show a temporary undo snackbar: the reverse action is always available from All or Search.
- Both mutations are checked for channel ownership by the server. Do not locally change the read state if the API operation fails.
