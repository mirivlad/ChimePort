# 06. Развёртывание и эксплуатация

**Текущий сервер v0.1.2:** зафиксированный образ — `ghcr.io/mirivlad/chimeport:v0.1.2`. Движущийся `:main` предназначен для разработческой проверки, не для спокойной эксплуатации. Для конкретной установки в Portainer см. [быстрый запуск](11-PORTAINER-QUICKSTART.md). Первая версионированная версия — v0.1.0; эксплуатационная надёжность Android остаётся экспериментальной.

## 1. Процесс установки

1. Создать DNS `notify.example.org`, направленный на VPS/домашний сервер с доступом по HTTPS.
2. Поднять обратный прокси (например, Caddy или Traefik) и получить сертификат TLS.
3. В Portainer создать Stack из опубликованного `deploy/compose.portainer.yaml` с фиксированной версией Docker-образа.
4. Подключить постоянный volume `/data`, а не хранить SQLite внутри эфемерного слоя контейнера.
5. Запустить безопасную процедуру создания первого администратора.
6. Создать пользователя, источник, канал и API-токен; проверить `curl` и получение сообщения.
7. Установить Android APK, ввести URL **своей** инсталляции, войти; Android поддерживает независимые серверы и локальное кэширование.
8. Проверить веб-панель и Android-клиент. PWA/Web Push пока не реализованы.

## 2. Требования к Docker-образу

- Один серверный контейнер, без обязательных Redis/PostgreSQL/брокера.
- Конфигурация через переменные окружения/файл; отсутствуют пароли по умолчанию.
- Volume `/data`: база, устойчивый instance_id, ключи, состояние установленных миграций.
- Healthchecks, читаемые логи, политика graceful shutdown, immutable version tag.
- Образы для `linux/amd64` и `linux/arm64`.
- Web-артефакты по возможности встроены в сервер, чтобы не заставлять пользователя разворачивать отдельный frontend.

## 3. Параметры окружения и планы

| Переменная | Смысл |
| --- | --- |
| `CHIMEPORT_PUBLIC_URL` | Канонический публичный URL (HTTPS) |
| `CHIMEPORT_LISTEN_ADDR` | Внутренний bind, например `0.0.0.0:8080` |
| `CHIMEPORT_DATA_DIR` | `/data` |
| `CHIMEPORT_LOG_LEVEL` | `info`, `debug`, `warn` |
| `CHIMEPORT_RETENTION_DAYS` | Хранение 30 дней по умолчанию, 0 отключает очистку (реализовано) |
| `CHIMEPORT_PUBLISH_RATE_PER_MINUTE` | 120 новых сообщений в минуту UTC на source token, 0 отключает (реализовано) |
| `CHIMEPORT_MAX_MESSAGE_BYTES` | Лимит размера payload |
| `CHIMEPORT_TRUSTED_PROXIES` | Ограниченный список доверенных reverse proxy |
| `CHIMEPORT_WEB_PUSH_ENABLED` | **Не реализовано**: не задавайте этот параметр, Web Push пока не работает |

Часть параметров реализована (см. пометки), остальные пока зарезервированы. Секреты не передавать в публичных `.env.example` с реальными значениями.

## 4. Reverse proxy

- HTTPS и перенаправление с HTTP.
- Передача корректных `X-Forwarded-*` **только от доверенного прокси**, не от произвольного клиента.
- Прокси должен поддерживать upgrade WebSocket (если этот транспорт будет выбран).
- Разумные таймауты для долгих соединений.
- Ограничение размера HTTP запросов и защита от грубого перебора.

## 5. Резервное копирование

Резервировать вместе: **снимок SQLite**, файл `/data/token-key` (ключ расшифровки токенов), instance ID, конфигурацию и будущие ключи Web Push/VAPID. Проверять не только наличие архива, но и восстановление на тестовом экземпляре. После восстановления Android должен узнать прежний `instance_id`; после намеренного создания нового сервера — новый.

Для обновлений: backup -> фиксированный tag новой версии -> миграция -> проверка health -> тестовая публикация -> при проблемах восстановление согласованной предыдущей версии. Обратимость миграций должна быть задокументирована; нельзя автоматически откатывать новую схему старым бинарником.

## 6. Домашние и публичные инсталляции

Self-hosted не означает, что можно бездумно выставлять сервер в Интернет. Админка требует нормальной авторизации, rate limit, TLS, актуальных образов. Поддержка LAN-only и локального CA сертификата — отдельный будущий сценарий с понятным UX на Android.

## Реализованный механизм обслуживания (M1.1)

Начиная с server maintenance CLI доступны проверяемые резервные копии работающего SQLite через VACUUM INTO, контроль соответствия token-key, восстановление **исключительно в пустой каталог**, и неизменяемые теги GHCR `sha-<full commit>`. Руководство с командами для Portainer: [Backup, rollback, restore](13-BACKUP-RESTORE.md). Существующий volume при восстановлении не перезаписывается, приложение переключается на новый bind mount через `CHIMEPORT_DATA_MOUNT`. Автоматизированный Web UI и внешнее хранилище/ротация ещё не добавлены.

## Новая схема SQLite v3

После бэкапа и проверки архива новая версия сервера автоматически мигрирует схему v1/v2 → v3. Старая версия не поддерживает v3; откат Docker-образа требует восстановления старого бэкапа. При первом запуске новой версии очистка удалит события старше 30 дней (если не задать `CHIMEPORT_RETENTION_DAYS`). Для отключения — значение 0.

Отправители должны обрабатывать 429 и заголовок Retry-After. При необходимости индивидуальные лимиты получают отдельными source tokens.

## Локальное создание токена интеграции (совместимо с v0.1.2)

Оператор с правами на Docker volume может выполнить `chimeport integration provision --username admin --source home-assistant --label ha --channels home --token-out /data/ha-token.tmp`. Команда создаёт или переиспользует каналы и источник выбранного пользователя, записывает **новый** токен в эксклюзивный файл 0600 и не выводит его в логи. Файл необходимо безопасно перенести в secret-хранилище интеграции и немедленно удалить из /data. При повторном запуске с существующим путём команда откажет, чтобы не потерять ранее выданный секрет. Это привилегированная локальная операция, не HTTP endpoint.

## Что поддерживается сейчас

Веб-панель и API встроены в Go-сервер; отдельный SPA/Node контейнер не нужен. Доступны SSE, Android alpha, ограниченные токены, управление пользователями, история, темы и maintenance backup/verify/restore. Текущая SQLite schema — 3. Web Push/VAPID/PWA в этом релизе отсутствуют. Детали установки и обновления — в [Portainer Quickstart](11-PORTAINER-QUICKSTART.md) и [Backup & Restore](13-BACKUP-RESTORE.md).
