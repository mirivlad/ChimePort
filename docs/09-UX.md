# 09. UI/UX: спецификация экранов

## 1. Веб-панель

### Обычный пользователь

- **Лента «Все»**: дата, канал, источник, заголовок, текст, приоритет, прочитано/непрочитано; фильтры и поиск; кнопка «Отметить прочитанным».
- **Каналы**: список, счётчик непрочитанных, просмотр одного канала; создать/переименовать/архивировать (владелец).
- **Источники**: название, описание, разрешённые каналы; список токенов с метками, сроками и последним использованием.
- **Создать токен**: имя (обязательно), описание, source, scopes, разрешённые каналы, срок жизни; токен можно повторно показать и скопировать в любой момент; разрешённые каналы выбираются **галочками по названию**, без ручного ввода ID.
- **Изменить права токена**: для действующего токена кнопка «Изменить права», текущие разрешённые каналы уже отмечены, сохранение атомарно меняет только права публикации, не перевыпуская секрет. Требуется минимум один канал; отозванные токены не редактируются.
- **Устройства**: веб-подписки, Android, время последней синхронизации, отзыв устройства.
- **Настройки**: язык, профиль, уведомления браузера, сроки хранения в рамках разрешённого админом.

### Администратор

- Создание пользователя, блокировка, сброс доступа, роли.
- Состояние сервера, health, версия, размер БД, retention, аудит административных действий.
- Никакой кнопки «прочитать чужую личную переписку/уведомления» по умолчанию.

## 2. Android: первое подключение

```text
[Добро пожаловать в ChimePort]
Адрес сервера: https://______________
[Проверить подключение]
  -> Сервер найден / ошибка TLS / неверный URL / несовместимая версия
Логин: _______
Пароль: ______
[Войти]
  -> Спросить разрешение на уведомления
  -> Зарегистрировать устройство
```

Разрешить самостоятельно задать удобную метку («Дом», «Работа»). Возможность быстрого добавления QR со **ссылкой сервера**, а не паролем; QR с одноразовым pairing-кодом — отдельная будущая возможность.

## 3. Android: экраны

- **Все уведомления**: объединённая хронологическая лента всех аккаунтов, карточка явно помечена сервером и каналом. Фильтр: сервер, канал, прочитано, приоритет.
- **Серверы**: добавить, переименовать, отключить, удалить с очисткой локального кэша; статус соединения/ошибки/последней sync.
- **Каналы**: по серверу, со счётчиками; лента одного канала.
- **Настройки звука**: глобальные значения -> переопределение для сервера -> для канала. Выбор системного звука и переход в Android settings конкретного системного канала.
- **Тишина**: старт/окончание, дни начала интервала, таймзона, полный день, пользовательский override только внутри правил приложения.
- **Диагностика**: разрешение уведомлений, статус foreground service, Android battery restrictions (насколько платформа позволяет определить), последняя синхронизация и последнее событие.
- **О приложении**: версия, лицензия, исходный код, конфиденциальность, импорт/экспорт только несекретных настроек.

## 4. Принципы UX

- Никаких обязательных cloud accounts; форма подключения всегда начинается с адреса **произвольного** сервера.
- Показывать точный домен, на котором пользователь вводит пароль.
- «Синхронизировано» не равно «уведомление показано ОС».
- Непрочитанное не равно недоставленное.
- В настройках канала должна быть кнопка «Проверить уведомление» (через серверный тестовый запрос, требующий пользовательскую авторизацию и не раскрывающий source token).
- Ошибки объяснять человеческим языком: DNS, TLS, 401, отключённые уведомления, задержка фона, mismatch `instance_id`.
- Светлая/тёмная темы, ru/en, доступность, размеры шрифта Android, никаких навязчивых анимаций.

## Повторный доступ к токенам

В карточке источника есть список токенов с именем, описанием, префиксом, сроком и статусом. Для действующего токена владелец может нажать **Показать**, **Скрыть**, **Копировать** и **Отозвать**. По умолчанию полный секрет скрыт, но **он не является одноразовым**: его можно посмотреть позже без пересоздания. Для отозванного токена отображаются только метаданные.

## 5. Реализовано в первой переработке веб-панели (M1 UX)

- Боковое меню: входящие, каналы, источники, пользователи.
- Первоначальная настройка поясняет цепочку «канал → источник → токен».
- Канал создаётся по названию: slug автоматически формируется и доступен в раскрываемом техническом поле.
- Источники представлены карточками. У каждого есть список токенов с отображением каналов, срока и статуса.
- Создание токена — полноценная форма с названием, описанием, **галочками выбора разрешённых каналов**, необязательным сроком действия и проверкой выбора. Никакого `prompt()` и числовых ID.
- Полный токен доступен повторно владельцу через «Показать/Копировать». В общем списке он скрыт.
- Адаптивная компоновка для мобильного браузера; API и схема БД сохраняются совместимыми.
- Администрирование пользователей в этом выпуске позволяет создать и посмотреть записи; изменение и сброс паролей ещё не реализованы.

## Адреса и токены на странице каналов

Для каждого канала показывается полный действующий URL публикации вида `https://chime.mirv.top/api/v1/messages?channel=home`, копируемый одной кнопкой. Кнопка «Токены» раскрывает все действующие токены владельца, у которых есть право публикации в этот канал, сгруппированные по источнику. Каждый токен можно показать, скопировать и отредактировать в общем диалоге прав; из диалога его можно также отозвать. Кнопка «Примеры отправки» в шапке ведёт на отдельную страницу `/examples` с типовыми рабочими примерами и выбором канала.
