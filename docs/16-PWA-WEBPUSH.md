# PWA и Web Push — ChimePort M3

> **Статус:** реализация в ветке M3, подготовка следующего релиза после v0.1.2. На текущем production-сервере v0.1.2 функция пока недоступна. До обновления необходимы бэкап, тесты и новый Docker-образ.

## Что появится

- Устанавливаемое веб-приложение: manifest, Service Worker, оригинальные иконки Android 192×192 и 512×512.
- Настройки **«Web Push → Включить/Отключить на этом устройстве»**. Разрешение запрашивается только по нажатию пользователя.
- Зашифрованные браузерные уведомления с VAPID (RFC 8292) и payload encryption (RFC 8291), даже при закрытой вкладке — если это разрешает ОС и браузер.
- Каждая подписка привязана к пользователю и конкретной серверной сессии: выход, смена/сброс пароля отзывают её. Блокировка пользователя прекращает доставку.
- Публикация в SQLite **до** постановки на доставку. Web Push — best effort, не источник истины: история и SSE продолжают работать независимо.

**Важно:** сервер ChimePort self-hosted, но Web Push использует шлюзы браузеров (Google FCM, Mozilla, Apple, Microsoft WNS). Шифрование скрывает содержимое от посредника, но тот может видеть метаданные доставки. Нет гарантии времени прихода и обхода системного Do Not Disturb.

## Подключение пользователем

1. Откройте свой ChimePort по **HTTPS**, войдите в аккаунт.
2. Перейдите в **Настройки → Web Push** и нажмите **«Включить уведомления»**.
3. Разрешите уведомления в системном запросе браузера. Если раньше отказали, смените разрешение вручную в настройках сайта.
4. Для теста отправьте обычное сообщение из источника через API или примеры `/examples`. Уведомление откроет панель и подсветит соответствующее сообщение.
5. **«Отключить на этом устройстве»** отзывает подписку этого браузера, остальные устройства продолжают работать.

**iPhone/iPad:** требуется iOS/iPadOS 16.4+ и запуск **с домашнего экрана**, а не обычной вкладки. Откройте меню «Поделиться» → «На экран Домой», запустите установленное приложение и включите Web Push. [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

**Linux/Windows/macOS:** Chrome и Edge поддерживают установку; Firefox на компьютере может принимать push, но не предлагает обычную установку PWA из manifest. [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Кэш и приватность

Service Worker расположен по `/sw.js`, scope `/`, manifest — `/manifest.webmanifest`. В Cache Storage остаются **только статические** HTML/JS/CSS/иконки. Никогда не кэшируются `/api/`, история, сессии или токены. При офлайне открывается оболочка, но история доступна только после соединения с сервером.

При клике на уведомление открывается `/?message=<id>` на том же сервере. Внешние URL из сообщений автоматически не открываются. Если сессия истекла, сначала потребуется войти.

## Реализованные маршруты (после выпуска M3)

| Метод | Путь после `/api/v1` | Назначение |
| --- | --- | --- |
| GET | `/webpush/vapid-public-key` | Публичный VAPID-ключ для вошедшего пользователя |
| POST | `/webpush/subscriptions` | Добавить/перепривязать подписку текущей сессии |
| DELETE | `/webpush/subscriptions` | Отозвать подписку по endpoint |
| GET | `/webpush/subscriptions` | Число подписок пользователя |

POST принимает `{"endpoint":"https://…","keys":{"p256dh":"…","auth":"…"}}`. Не посылайте поле `expirationTime`: сервер ожидает endpoint и keys.

**Защита от SSRF:** только HTTPS-адреса известных push-шлюзов, без userinfo, IP-адресов, портов и редиректов. Перед соединением проверяются публичные IP разрешённого hostname. Лимит: 16 подписок на пользователя. После HTTP 404/410 подписка удаляется. TTL — 1 час. Подписки продолжают получать push после истечения веб-cookie, пока серверная запись сессии не отозвана; вход для просмотра истории всё равно понадобится.

## VAPID, SQLite и откат

- M3 повышает SQLite **schema 3 → 4**, добавляет `webpush_subscriptions` и сохраняет постоянные VAPID-ключи в таблице `instance`.
- Приватный ключ **зашифрован ключом** `/data/token-key`. Существующая процедура backup/verify/restore сохраняет и SQLite, и token-key; схема 4 поддерживается.
- Старый сервер v0.1.2 **не умеет открывать schema 4**. Перед обновлением сделайте проверенный архив старой схемы; для отката используйте старый образ вместе со старым архивом в новом каталоге, не старый образ поверх новой БД.
- VAPID-ключ нельзя генерировать заново при рестарте/обновлении: это приведёт к потере действительности браузерных подписок.

## Ручная приёмка до релиза

1. Chrome, Edge, Firefox desktop, Android Chrome; отдельно Safari macOS и iOS/iPadOS Home Screen.
2. Уведомления при открытой и закрытой вкладке; запрет доступа, отсутствие сети, системный DND и повторная синхронизация.
3. Выход, смена пароля, блокировка пользователя, повторный вход, чужие подписки, удаление endpoint при 410.
4. Бэкап schema 4, verify и восстановление в пустой каталог с тем же instance ID и VAPID.
5. Проверка, что push-клиент **не может** обращаться к произвольным хостам, и сообщение сохраняется до HTTP 201.
6. Web Push остаётся **негарантированным** каналом: для критических сигналов используйте независимую доставку.
